# D-4 Presenter Mode —— 提词卡与逐字稿双轨（原理重写版）

> 依据：html-ppt 演讲者模式（MIT）+ guizang 演讲者契约原理（AGPL-3.0，**只学原理、不引原文**）。
> 定位：Generate PPTX 生成期的**讲述内容纪律**，承载物是原生 PPTX 备注区。
> 冲突处理：`design_spec.md` + `spec_lock.md` 仍是唯一规划权威；本文件只规定讲述层内容。
> 吸收对照见文末。

## 1. 双轨制

| 轨道 | 何时使用 | 产物 |
|---|---|---|
| **提词卡（默认）** | 未明确要求逐字稿 | 每页要点式提要（3–5 条）+ 转场句 |
| **逐字稿（显式）** | 用户明确要求"逐字稿/口播稿/照读" | 每页 150–300 字完整口语稿 |

**P-0 默认纪律**：默认产出提词卡，不得擅自升格为逐字稿。
逐字稿只在用户显式要求时生成；已给成稿（final/literal script）时按 base 规则**保留原词**、只做校验。

## 2. 逐字稿三条硬规则

**P-1 提示信号，不是讲稿复印**：讲述内容必须补充页面上**没有**的信息（背景、依据、判断、例子），
不得逐字复述上屏文字。逐字稿与上屏文案的重复率越低越好。

**P-2 篇幅 150–300 字/页**：少于 150 字说明信息量不足（或该页本就该更短）；
多于 300 字说明该页承载过重，应考虑拆页或把细节移出讲述。
封面/章节页/纯过渡页可以更短，不受 150 字下限约束。

**P-3 口语，不是书面语**：写"能说出口的句子"。
- 不用书面连接词堆砌（"综上所述""基于此"），用口语过渡（"说到这里""接下来看"）
- 数字按口语读法写（中文"百分之六十八"优于"68%"），避免 TTS 读错
- 单一语言，不中英混排
- 不含 Markdown 列表符、`要点：`、`时长：` 等元信息（base 备注会被 TTS 逐字朗读）

## 3. 字段结构

```yaml
id:            # 必填。页面 slug 主键，小写英文（如 cover / market-evidence）
title:         # 必填。页面标题
purpose:       # 必填。本页在整场中的沟通目的（一句话）
talk:          # 必填。3–5 条讲述要点；逐字稿模式下为完整段落
transition:    # 必填。通向下一页的自然转场句（解释"为什么接着讲这个"）
minutes:       # 可选。本页建议讲述时长（分钟）
cue:           # 可选。停顿/Demo/视频/敏感信息提醒
interaction:   # 可选。提问/举手/投票/问答
delivery:      # 可选。语气、重音、语速、停顿提示
fallback:      # 可选。Demo/视频/网络失败时的备用说法
pronunciation: # 可选。人名/缩写/外语读音
autoAdvanceSeconds:  # 可选。本页自动停留秒数（播放行为）
```

**P-4 缺失隐藏，不猜**：用户大纲未提供的信息一律省略字段，**不得**写"待补充""TBD"或编造。
界面侧对缺失项显示中性横杠或整段隐藏。

**P-5 覆盖完整**：讲述内容须覆盖页面上每个承载独立信息的元素（标题、每个信息组、图表结论），
不得为了凑条数而漏掉独立信息组；也不得为覆盖而啰嗦复述装饰元素。

**P-6 讲述时长与播放时长分离**：前者是 `minutes`（讲述计划），后者是 `autoAdvanceSeconds`（播放行为）。
不得因为"这页打算讲 1 分钟"就默认 60 秒后自动翻页。

**P-7 总时长 ≤ 现场 90%**：全部 `minutes` 之和不得超过给定现场时长的 90%，留出缓冲。
仅在每页都有 `minutes` 时才计算总时长；部分缺失时不给总数。

## 4. 稳定 ID 纪律

**P-8 slug 主键，禁页码**：每页 ID 必须是语义化、稳定的英文 slug。
- 页面重排时**保留原 ID**
- 只有页面语义彻底改变时才更换 ID
- 绝不使用页码作 ID（重排后会串页）

**P-9 一一对应**：讲述记录的数量、顺序必须与最终页序逐页一致。
页数增减必须先做 Spec repair，再同步讲述记录；不允许只改一边。

## 5. 承载映射（PPTX 语境）

| 机制 | PPTX 承载 | base 锚点 |
|---|---|---|
| 提词卡 / 逐字稿正文 | 备注区（notes slide） | `notes/total.md` → `total_md_split.py` → `svg_to_pptx.py` |
| 关闭备注 | 不生成备注 | `svg_to_pptx.py --no-notes` |
| 讲述转语音 | 备注逐字 TTS | `stages/generate-audio.md` + `notes_to_audio.py` |
| 提词文档（可选） | 独立 Markdown 提词稿 | 项目内 `notes/` 目录，Markdown |
| 观众屏同步 | **不适用** | 原生 PPTX 无观众屏进程；留给 M2 验稿器（HTML 预览） |
| 激光笔/圈选/黑屏 | **不适用** | 由 PowerPoint 自身提供；D-4 不实现 |
| 实时字幕/语音转写 | **不适用** | 能力边界外 |
| AI 排练教练/评分 | **不适用** | 明确不做（见 §6） |

**P-10 备注纯净性**：写入备注区的文本必须"可照读"——因为 `notes_to_audio.py` 会逐字朗读。
不得写入标题行、`- ` 列表符、`[过渡]` 之类的标记。

**P-11 承载选择**：提词卡（要点式）与逐字稿（完整段落）不得混写在同一页备注里。

## 6. 排练数据契约

**P-12 只汇总，不评分**：排练记录（每页实际用时、总用时）只做数据汇总，供主持人对照计划；
**禁止**生成"讲得好不好"的评判、评分或 AI 教练式建议。

**P-13 计划 vs 实际分离展示**：同时呈现总实际时长、本页实际、本页计划、剩余或超时；
缺 `minutes` 的页显示横杠，不推算。

**P-14 计时显式启停**：计时由用户显式开始，可暂停/继续/重置；不自动启动。
动作名明确（"开始计时 / 继续计时 / 重置计时"），不用孤立的"开始"。

## 7. 能力边界

本增量**只**产出讲述内容与备注承载契约，明确不含以下能力：

- 实时字幕 / 语音转文字 / 外部语音模型
- AI 排练教练 / 对演讲者评分
- 扫码提问 / 在线投票 / 云端互动后台
- 手机遥控 / 需要服务端中继的跨设备控制
- 观众屏进程与物理外接屏检测（PowerPoint 自身职责）

## 8. 校验对接

| 条款 | 检测方式 | 建议挂载点 |
|---|---|---|
| P-0 双轨判定 | 人工：确认用户是否显式要求逐字稿 | Strategist 确认门 |
| P-1 非复述 | 半自动：与页面文本重叠率统计；判定需人工 | 扩展校验器 + 人工 |
| P-2 篇幅 150–300 | 可自动检测：逐页字数 | 扩展 D-2/校验器 |
| P-3 口语化 | 半自动：可查 Markdown 标记/元信息残留；口语度需人工 | grep + 人工 |
| P-4 缺失隐藏 | 可自动检测：备注/字段中是否出现"待补充/TBD" | 扩展校验器 |
| P-5 覆盖完整 | 人工检查：逐页对照信息组 | 人工（评审） |
| P-6 minutes/autoAdvance 分离 | 可自动检测：两字段是否被耦合推导 | 扩展校验器 |
| P-7 ≤90% | 可自动检测：`minutes` 求和 vs 现场时长 | 扩展校验器（需入参现场时长） |
| P-8 稳定 slug | 可自动检测：ID 是否为页码 / 重排后是否保留 | 扩展校验器 |
| P-9 一一对应 | 可自动检测：讲述记录数/序 vs 页序 | 扩展校验器 |
| P-10 备注纯净 | 可自动检测：备注中 Markdown 标记/标题行残留 | 扩展校验器 |
| P-12 只汇总不评分 | 人工：确认无评分字段 | 人工 |
