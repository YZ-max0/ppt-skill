# 发起引导协议（intake guide）

> 面向执行者：**用户说一句话之后，你怎么问、怎么定、怎么开工。**
> 面向使用者：你只需说清"要做什么"和"要多好"，其余按默认值推进。
> 相关：`docs/USAGE.md` §8、`docs/QUALITY-TIERS.md`、`deltas/director.md`

---

## 1. 入口一问

收到任何制作请求后，**先问这一个问题**（除非用户已明确表达）：

```
这份 PPT：是要快，还是要尽可能做好？
（没特别说的话，我按"尽可能做好"来做）
```

为什么这样问：用户实测反馈"六项输入门槛太高"，且"不选快速 = 想要尽可能高质量"。
所以**只问一个二分问题**，其余判断留在协议内部。

用户回答后走对应分支：**§2 尽可能好**（默认） 或 **§3 要快**。
用户说"随便/你看着办/都行" → 走 §2，并在交付说明里注明"按默认高质量执行"。

---

## 2. "尽可能做好"分支 = 质量协议

### 2.1 流程深度：按内容量伸缩

| 内容量 | 走什么 |
|---|---|
| **≤12 页** | **轻量稿**：先定受众视角，再逐页写"标题 + 要点 + 页型"；不额外做视觉专项打磨 |
| **>12 页 或 重要场景** | **完整流程**：先想清楚给谁看 → 逐页稿 → 视觉专项 → 内容复核 → 生成 |

"重要场景"== 决策者/管理层/评审委员会/投资人，或用户明确说"重要/正式/要给领导看"。
两者冲突时取**更重的**那条。

### 2.2 质检：不打折

无论上面走哪条，**质检一律拉满**：

1. **四道自动检查**：结构校验、出框检测、标题一致性、跨组重叠、内容泄漏
2. **渲染目视**：出缩略总览并做人眼复核（含图片的页尤其必须）
3. **内容复核默认挂载**：按五视角挑刺（逻辑/受众/风险/标题/缺失），产出返修项

> 内容复核在"轻量稿"场景同样挂载——它查的是**内容对不对**，与页数无关。

### 2.3 视觉：给候选，不替用户决定

- 展示 **2–3 个视觉候选**（一句话描述 + 可看图），让用户挑
- 用户说"你决定" → 用**增强版**（封面强化、图表页、图片位、节奏锚点）；**不得默认给克制版**

### 2.4 演讲稿：按场景问

- **要上台讲**（分享/评审/路演）→ **问**：要逐字稿还是提词卡？
- **交材料**（审阅/存档）→ **提词卡**，不问

逐字稿 = 每页可照读的口语稿；提词卡 = 每页 3–5 条要点 + 转场句。

## 3. "要快"分支 = 轻量通道

**不问内容细节**，直接按默认值推进：

| 项 | 默认 |
|---|---|
| 流程 | 选页面样式 → 填内容 → 过结构校验 → 导出 |
| 页数 / 风格 / 备注 | 6–8 页 · 简洁克制（不给视觉候选）· 不生成备注 |

**必须标注假设**：交付时列清"哪些是推测的"（受众、页数、风格、数据来源等），
用户据此判断要不要调。

若用户在快通道中途要求"再做好一点" → 转 §2，已产出内容沿用。

## 4. 引导原则（AI 行为规范）

**总则 · 自然语言优先**：用户说一句话就够。你**只问缺的关键项**，
不要要求用户按模板填写（模板见 §6）。

**N-1 · 术语禁令**（对用户可见的文字）
禁说内部术语，一律换成场景语言。常见对照：

| 不说 | 说 |
|---|---|
| 走完整流程还是轻量稿？ | 这份要仔细打磨，还是尽快出稿？ |
| 用视觉增强还是克制版？ | 想做得醒目一些，还是稳重一些？ |
| 选哪个版式？ | （不问——你直接选，只在其方案有歧义时给候选） |
| 要不要挂内容终检？ | （不问——按 §2.2 默认做） |
| 受众画像是什么？ | 这份主要给谁看？他们最在意什么？ |

> 本文档在"对照表"处必须列出这些词，属**元说明**；
> **与用户的对话中一律不得出现**（§5 两个示例对话为合规样本）。

**N-2 · 跳过永远在**
每个问题都附一个"其他，你来定"的选项。用户跳过 → **用默认值 + 标注假设**，
不追问、不卡住。

**N-3 · 一次最多 3 问**
超过 3 个问题就按默认值先推进，剩下的等交付后按需再调。

**N-4 · 能默认不问**
页数、时长、风格若可从内容推断，**不问**，直接做默认并注明。

## 5. 两个完整示例对话

### 例 1 · "帮我做一份下周团队周报"

> **用户**：帮我做一份下周团队周报

> **你**：好。一份就够，还是需要我先给你看个结构？（其他：你直接定）

> **用户**：你直接定

> **你**：明白，我按"简洁出稿"来做，6 页走：
> 封面 / 本周完成 / 风险与对策 / 下周计划 / 关键数据 / 小结。
> **假设**（会写进交付说明）：受众=你的直属主管；内容为通用团队模板；
> 数据为占位，需你回填。约 5 分钟出稿。

> **用户**：可以

**（无更多追问，直接开工；交付时逐条列出上面的假设。）**

---

### 例 2 · "下周要给分管领导汇报平台建设方案"

> **用户**：下周要给分管领导汇报平台建设方案

> **你**：这份是要快，还是要尽可能做好？
> （没特别说的话，我按"尽可能做好"来做）

> **用户**：尽量做好

> **你**：好。两件事确认一下就可以开工：
> ① 分管领导最关心的是**投入产出**，还是**落地节奏和风险**？
> ② 这次是**上台讲**，还是**交材料给他看**？
> （其他：你来定）

> **用户**：关心投多少钱、多久见效。要讲的，大概 20 分钟

> **你**：收到。20 分钟 + 决策者 → 我走完整打磨流程，页数按 18–22 页。
> 视觉给你三个方向，看哪个顺眼：
>
> - **A 稳重款**：白底为主，蓝色主色，数据用大字和表格 —— 像一份正式立项报告
> - **B 醒目款**：封面和关键页用深色大色块，数据用图表 —— 汇报时更有冲击力
> - **C 均衡款**：A 打底，关键 3–4 页用 B 的手法做重点
> （其他：你直接定，我倾向 C）

> **用户**：B 吧

> **你**：好，视觉用 B。最后一项：**要不要逐字稿**？（每页可照念的口语稿，按 20 分钟配速）

> **用户**：要

> **你**：齐了，开工。开始前说一句我打算怎么做：
> 先把"给谁讲、他关心什么、讲完希望他拍什么板"定死，再逐页列出每页要说的结论，
> 然后做视觉、挑刺、出稿。做完先给你一页缩略总览过目。
> **假设**：经费与工期数字需你提供；未提供前我用占位并标注。

**（追问 2 轮、共 5 问，其中 3 问带"你来定"；随后进入完整流程。）**

## 6. 精确模式（原六项输入模板）

**何时用**：批量制作、团队协作需留档、或你已有明确素材路径与硬性约束。
**何时不用**：日常一句话需求——走 §1 引导即可。

```
请制作一份 PPT。

1. 主题：<一句话说明要讲什么>
2. 受众：<谁听 + 人数 + 他们最关心什么>
3. 页数：<6-8 页 / 18-22 页 / 其他>
4. 时长：<5-8 分钟 / 20-30 分钟 / 其他>
5. 素材：<文档路径 / 数据 / 仅口头描述；无则写"无素材，允许自拟并标注假设">
6. 风格偏好：<简洁克制（默认）/ 更醒目 / 其他>
```

**可选补充**：是否需要演讲者备注（逐字稿 or 提词卡）、是否有指定页型或配色、交付形态（仅 .pptx / 需要缩略总览）。

> 用精确模式时，§2/§3 的质量分支仍然生效——**模板只是把信息一次给全，不改变质量协议**。

## 7. 决策速查

| 用户说了什么 | 怎么走 |
|---|---|
| "随便看看 / 先出个草稿" | §3 快通道 |
| "看着办 / 都行 / 没想法" | §2 默认高质量 + 交付注明"按默认执行" |
| "要给领导/客户/评审看" | §2，且按"重要场景"取完整流程 |
| "简单点 / 别啰嗦 / 就几页" | §3 快通道 |
| 中途说"再做好一点" | 转 §2，已产出内容沿用 |
| 只给了素材文件、没说别的 | §1 问一句 + 从素材推断页数与结构（N-4） |
