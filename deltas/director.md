# D-1 Director Workflow —— 导演式工作流（原理重写版）

> 依据：ppt-director 原理（无许可证，仅学原理不引原文）。
> 定位：本增量是 Generate PPTX 路由的 **Pre-spec 输入阶段**（详见 DELTAS D-6 挂载条款），
> 解决 base 缺失的"重要汇报想清楚"链路。导演稿是 base `design_spec.md` 的**入料**，
> 不是平行权威（冲突处理见 §6）。

## 1. 路线裁决（导演式是否启用）

| 输入特征 | 路线 |
|---|---|
| 仅主题/想法/不完整材料 | 导演式（A→B→B2→C） |
| 重要汇报（决策者/管理层/评审）+ ≥10 页 | 导演式（受控，完整 4 阶段） |
| 素材完备、页数 ≤8、时效紧 | 快速通道（轻量导演稿，直接进 quick-generate） |
| 已有成稿 PPTX | base：Enhance Native / Beautify 路由，不经导演 |
| 用户明确"简单点/别啰嗦" | 快速通道 |

## 2. 阶段序列

| 阶段 | 目的 | 交付物 | 门禁 |
|---|---|---|---|
| A · 受众画像 | 确认给谁听、他们关注什么、讲完要什么结果 | 受众卡（5 字段，见 §3） | 无硬门禁；3 句以内钉死视角 |
| B · 内容打磨 | 立骨架：页数预算、逐页观点 | 大纲 + 逐页导演稿（§4） | 导演稿不得写设计语言（强约束） |
| B2 · 页面视觉导演优化 | 把"内容稿"升级为"可设计稿" | 优化版：逐页上屏短句 + 主视觉承担逻辑 | **硬门禁：原始 MD 必须过此阶段才进生成** |
| C · 映射进 base | 导演稿 → design_spec 入料 → lock → SVG → PPTX | base 标准管线 | base 确认门（一次确认，见 §6.4） |

## 3. 受众卡（A 阶段，5 字段）

`听众身份`（决策者/管理者/工程师/投资人/评审）`· 关注点`（3 条，驱动力排序）`· 演讲目标`（会后要发生什么决策）`· 知识底色`（术语尺度，技术深度上限）`· 禁忌`（不能踩的规则/立场）。

## 4. 页面结构导演稿（B 阶段，每页 10 字段）

| # | 字段 | 要求 |
|---|---|---|
| 1 | 页面标题 | 观点句（主题+判断/动作），禁纯名词 |
| 2 | 本页核心结论 | ≤40 字，唯一判断，不重复标题 |
| 3 | 页面类型 | 8 选 1：分层架构 / 业务流程 / 能力体系 / 对比分析 / 场景价值 / 实施路径 / 案例成效 / 机制说明 |
| 4 | 页面版式 | 顶部/主体/侧边/底部 + 信息密度档 |
| 5 | 主视觉设计 | 主视觉必须解释逻辑，不是装饰 |
| 6 | 主视觉内容 | 按区域/层级/步骤 1..N 列出必出元素 + 必要解释 |
| 7 | 面积预算 | 主视觉 ≥55%（流程页 ≥60%），辅助 ≤30%，收束 ≤15% |
| 8 | 上屏文案 | **唯一上屏栏**：模块标题 4-8 字、说明 12-24 字；长解释进备注 |
| 9 | 收束总结 | 底部一句话：价值/结论 |
| 10 | 生成风险 | 关系不清/主视觉被抢/连接线方向/区域词误上屏 |

**区域词清洗规则（本增量最重要的单条纪律）**：`左侧/右侧/顶部/底部/中部/侧边/上方/下方` 在导演稿里只允许出现在"页面版式"和"主视觉内容"栏（排版语境）；"上屏文案"栏若出现区域词前缀（如 `左侧：某平台`），生成阶段必须清洗为 `某平台`。排版指令（弱语义）与上屏语义（强语义）不得混用。

**内容/视觉分离纪律**：导演稿只写"内容结构"，即用户看到的内容和逻辑；不写颜色、字体、坐标、风格参数——那属于 base 的 design_spec/lock 层。换风格=只换设计层，导演稿不动。

## 5. 生成就绪转换（B2→C 桥）

导演稿进入 base 前的转换动作（供 Strategist 使用，不是平行文档）：

1. 逐页导演稿 → `design_spec.md §IX`（页内容权威，一对一、页序一致，增删页先做 Spec repair）
2. 受众卡信息 → §I 通信契约（称呼/口吻/主题深度），用途：主题词、内容深度的定调
3. 主视觉内容（区域清单）→ 组件映射意向 + `preset-shape-vocabulary` 勾选（流程图/矩阵/分层由 base 原生形状词汇落地）
4. 生成风险项 → 质量门注意项（verify-charts/visual-review 必查点）
5. 上屏文案 → 每页正文的一手源，Excel 级"不可跳步"：SVG 文本不得脱离 §IX 自创

## 6. 与 base 的冲突处理（集成契约，写死）

| 冲突 | 决策 |
|---|---|
| 双重规划权威 | **base 的 design_spec + spec_lock 是唯一权威**；导演稿只作入料，Stategist 消费后丢弃，不平行维护 |
| HTML vs SVG 基准 | **SVG 是唯一可见内容源**；HTML 预览仅作门禁前视觉确认物，不作为 PPTX 建档内容 |
| 页序主权 | 交付文档页序先对齐 §IX；页数增减必须先 Spec repair |
| 双确认门 | **合并为一次最终确认**：base 的 Confirm UI 最终态 = 导演链路的人工确认门（含 contact sheet/审查摘要） |
| 固定资产 | 从 deltas registry 复制/登记进项目 `images/` + design_spec §VIII；只引用不可生成 |

## 7. 快速通道（副轨轻量）

受众 3 句 → 每页"观点标题 + ≤3 要点 + 页型" → 直接进 base `quick-generate`；跳过 B2 优化与 C 阶段全部行文细节。

## 8. 评审卡（可选挂载，按场景启用）

5 个挑刺视角：逻辑（论证链完整？）· 受众（每页信息是听众关心的吗？）· 风险（敏感点/争议点处理）· 标题（能不能反着读？）· 缺失（答辩可能追问什么）。T-04/T-06 测试场景要求挂载。
