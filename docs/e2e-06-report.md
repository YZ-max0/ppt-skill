## 6. 失败模式（C-XXX）

### C-023 · 标题数据与图形矛盾（**真实错误，评审卡逻辑视角发现，已修**）

- **现象**：P06 标题"查询量增长三倍，响应时间反降**四成**"，
  但图上 Q1 8.4s → Q4 3.6s，实为**降 57%**。
- **根因**：撰写标题时凭印象取整，未回算图上数据。
- **为何四道闸全漏**：数字都在 bounds 内、无重叠、无泄漏——**纯内容错误**。
- **修复**：改为"反降**六成**"（57% 取整到六成）。
- **教训**：**标题里的每一个数字都必须能由同页数据复算出来**。

### C-024 · 证据数值链自相矛盾（**真实错误，评审卡逻辑视角发现，已修**）

- **现象**：P13 同时写"迁移总量 4.2 亿条"、"差异率 0.03%"、"差异台账 1,284 条"。
  但 `4.2 亿 × 0.03% = 12.6 万条`，与 1,284 条**相差 98 倍**。
- **根因**：三条证据分别撰写，未做**交叉验算**。
- **发现方式**：评审卡"逻辑"视角的论证链检查（自动工具无法发现）。
- **修复**：改为"差异台账 **12.6 万条**，已处理 **12.47 万条**"（1,284 为剩余未处理数，口径自洽）。
- **教训**：**百分比与绝对值同页出现时必须交叉验算**——这是财务/数据类汇报的高频硬伤。

### C-025 · 三期预算缺失（**真实缺口，评审卡缺失视角发现，已补**）

- **现象**：P14 质询五问"三期是否继续投入"、P19 请求"同意三期立项"，
  但**全篇未出现三期预算金额**。委员会必然追问"多少钱"。
- **修复**：P14 补"三期申请预算 **620 万元**"及分项证据；
  应答小结同步改为"建议续投，申请 620 万元，并设三条止损条件"。
- **教训**：**"请求批准"类页面的下一问永远是"多少钱/多久/谁负责"**，
  评审卡"缺失"视角应固定检查这三项。

### C-026 · 契约边界：column 只有 2 个类目（**评审卡受众视角连带发现，已修**）

- **现象**：P05 初版只有"一期/二期"2 个类目，而 `charts_index.json` 对 `column_chart`
  写明 *Pick for single-series category value comparison, **3-8 categories***——**低于下限**。
- **发现方式**：评审卡"受众"视角追问"这页是委员会关心的吗"，进而核对图表契约时发现。
- **修复**：补入"三期规划"作第 3 个类目，标题同步改为"由 11 个增至 19 个，三期规划至 26 个"。
- **教训**：**类目数也是契约的一部分**，选型时不能只看"是单序列柱状图"。

### C-027 · 同数字双口径歧义（**评审卡风险视角发现，已修**）

- **现象**：`1.8%` 在 P04 是"扩围口径结项值"、在 P07-Q1 是"可比口径起点"。
  两个数字相同、含义相反（一个是"未达标"，一个是"起点"），评审席极易混淆。
- **修复**：P07 图例改为"投诉率（可比口径·**非扩围口径**）"，
  脚注明写"Q1 的 1.8% 与 P04 结项值数字相同但口径不同"。
- **教训**：**同一 deck 内重复出现的数字必须能一眼区分口径**。

### C-028 · 返修引入的溢出（**自建回归，已修**）

- **现象**：按评审卡返修后（P07 脚注加长、P14 补预算行），checker 报 `blocking: 2`：
  P07 note 横向溢出 12.1%、P14 证据行溢出容器 7.4%。
- **根因**：返修时只改文字未复核容器宽度。
- **修复**：缩短 P07 脚注（改为"口径：二期初冻结的可比口径。Q1 的 1.8% 与 P04 结项值
  数字相同但口径不同。"）、拆分 P14 预算行（"三期预算 620 万元，分三项列支（详见建议书）"）。
- **教训**：**返修必须重跑质检**——内容改动会破坏几何，这是"改稿回归"的必然代价。

## 7. 未验证项（诚实披露）

| 项 | 说明 |
|---|---|
| **评审卡是人工过程** | 5 视角全部由执行者人工执行，**无自动化支撑**；其产出质量取决于挑刺者的水平与诚实度 |
| 评审卡独立性 | 本轮评审卡由**执行者本人**执行，非独立评审者——存在"自己审自己"的盲区。§2.2 的 L-1/L-2 之所以被发现，是因为刻意按"找自己的错"执行 |
| 真实答辩场景 | 质询清单为模拟；真实评审会的追问范围更宽，M-1~M-5 只是预判 |
| 投影环境 | 深色锚点页（P01/P19）未在偏色投影下实测 |
| 表格类页型 | 本 deck 用 `defense-answer`（左右分栏）而非真正的"表格"；`charts_index` 的 `tables/` 族未涉及 |
| L3 人工评审 | 本轮为执行者自查（contact sheet 目视），非独立评审 |

## 8. 《建议》

1. **把评审卡登记为 B3 阶段（内容终检）**。本轮实测证明它是"生成前最后一道闸"，
   而非"评审后复盘"。建议在 `deltas/director.md` §2 阶段表显式登记，并写明其输出是"改稿指令"。
2. **评审卡补三条固定检查项**（源自本轮高频发现）：
   ① **数字复算**：标题中的数字能否由同页数据算出（C-023）
   ② **百分比交叉验算**：百分比与绝对值同页时是否自洽（C-024）
   ③ **批准类页三问**：多少钱 / 多久 / 谁负责（C-025）
   这三条覆盖了本轮 7 项返修中的 4 项。
3. **"类目数/项数"纳入图表选型检查**（C-026）。`charts_index` 的规则里带明确数量区间
   （如 `column_chart` 的 3-8、`funnel_chart` 的 3-5、`bullet_chart` 的 3-7），
   建议做一个轻量校验：填充前断言各类目数落在规则区间内。
4. **抽取"同数字多口径"检查**（C-027）。可自动化的部分：扫描同一 deck 内
   重复出现的数值，若出现在不同页且上下文含"口径"字样，提示人工确认。
5. **返修后强制重跑四道闸**（C-028）。当前流程已是如此，但本轮是**踩到才知道**——
   建议在 `USAGE.md` 明写"任何返修后必须重跑 C3–C8"，避免"改完直接交付"。
6. **图片能力仍是最大缺口**（延续 `visual-review-04.md` 结论）。本轮 P15 用证据墙
   （数据卡）替代了图片位；真实评审 deck 常需架构图/现场照片，建议排入"图片位骨架"。
