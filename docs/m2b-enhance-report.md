### 5.4 《建议》附录

**建议 1【优先级高】需人类目视对比两张 contact sheet**
程序化指标（唯一色数）只能证明"元素量变化"，**不能判断"好不好看"**。
建议人类并排打开：
```
...\ppt-render\t03\contact-sheet.png        (v1 原版)
...\ppt-m2b\render-t03v2\contact-sheet.png  (v2 增强版)
```
重点看：① 封面是否"更强" ② 锚点页是否突兀 ③ 混用是否有割裂感。
**这是"视觉增强"是否成功的唯一可靠判据。**

**建议 2【优先级中】C-011 的普适教训写入 CONTRACT**
"骨架自检通过 ≠ 填充安全"——建议在 `../v0/CONTRACT.md` 补充：
**骨架的占位文案必须写成"该槽位允许的最长内容"**，否则 checker 验证的是空槽而非满槽。
本次 `cover-bold` 即因占位文案过短而漏过验证。

**建议 3【优先级中】C-010：subtier 可考虑再分一层**
当前 `short`（≤5 vw）同时容纳"条目名/标签"与"数值/短结果"。
可增加第四类 `value`（纯数字 + 单位，如 `40 万`/`秒级`/`1.8 年`），
从 `short` 中分离。数据支撑：本次 3 项误报的 18pt 全是数值标签。
**但需注意止损条款（T-FIX3）已用掉一次机会**，建议先积累更多样本再决定。

**建议 4【优先级中】W-6 更新**
`project_manager.py init` 有 `--dir` 参数可直接指定基目录，**比 `Set-Location` 更可靠**
（本次两次踩到 `Set-Location` 无效的场景）。建议更新 `docs/windows-notes.md` W-6。

**建议 5【优先级低】图表坐标自动计算**
当前 bar-chart 的柱高（290/145/87/58px）是按公式手工算的。
若图表骨架被频繁使用，建议写一个"数据 → 骨架填充"的小工具，
避免手工算错（本次未出错，但存在风险）。
