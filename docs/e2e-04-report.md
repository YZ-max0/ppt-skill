## 2. 图表选型理由表（按 `charts_index.json` 规则）

T-04 原文给的是"实验数据表 + **4 张折线图数据**"。按契约三步法接入，
**选型逐条对照规则原文**，不按直觉：

| 页 | 数据关系 | 选用 | `charts_index` 规则原文 | 判定要点 |
|---|---|---|---|---|
| P06 | 吞吐与 p99 随并发变化，**量纲不同**（req/s vs ms） | `dual_axis_line_chart` | *Pick for comparing 2 metrics with **different units/scales** over time. Skip if both metrics share the same unit (use `line_chart`).* | 两条序列单位不同 → 必须双轴，不能共用一条 Y 轴 |
| P08 | 缓存命中率随周次变化，**单一时间序列** | `line_chart` | *Pick for 1-3 time-series on a continuous axis showing direction. Skip if … different units (use `dual_axis_line_chart`).* | 同单位、看方向 → 单轴折线即可 |
| P10 | FP16/INT8/INT4 三档下，**两个指标同屏对照** | `column_chart`（多序列） | *Pick for single-series category value comparison, 3-8 categories. Skip for … multi-series (use `grouped_bar_chart`).* | ⚠️ 见下方"规则冲突处置" |
| P13 | 六项措施的**完成度百分比** | `progress_bar_chart` | *Pick for 3-8 items each with a **completion %**. Skip if items have explicit target+actual values (use `bullet_chart`).* | 只有完成度、无目标基线 → progress 而非 bullet |
| P17 | 显存占用随月份**累积增长** | `area_chart` | *Pick for 1-2 cumulative trend series **emphasizing volume** over time. Skip for … pure direction without volume (use `line_chart`).* | 强调量级而非方向 → area |

### 规则冲突处置（P10）

`charts_index` 对 `column_chart` 明确写 *Skip for … multi-series (use `grouped_bar_chart`)*。
本轮 P10 用了**多序列 column**，偏离了该条。理由与处置：

- 本仓库 `fill_chart.py` 的 `column` 渲染器**本身即支持多序列并排**（等价于 grouped bar 的几何），
  与 base 的 `column_chart`（单序列）与 `grouped_bar_chart`（多序列）是两个文件的分工不同。
- **如实记录偏差**：这是"实现合并了 base 两个模板的语义"造成的命名错位，
  不是有意违反规则。若要严格对齐契约，应把该渲染器拆名为 `grouped_bar`。
- **已列入《建议》**（见 §6-3）：`fill_chart.py` 的 `column` 应改名或拆分，避免与契约措辞打架。

## 5. 失败模式（C-XXX）

### C-015 · 图例与类目标签同排相撞（**真实缺陷，已修**）

- **现象**：P06/P08/P10/P17 的图例文字与横轴类目标签**叠印**在一起
  （如 P10 的"相对吞吐（倍）"压在"FP16"上）。
- **根因**：`fill_chart.py` 把图例基线设为 `CAT_Y = 600`，与类目标签**同一行**。
  这是渲染器初版就存在的设计错误，T-E2E3 的 T-02 deck **未配色块图例**（P06 line 有图例、
  但当时只有 3 个点、类目标签少，未暴露到肉眼可见程度），故一直没被发现。
- **为何 checker 拦不住**：图例与类目标签**分属两个 `<g>`**（`legend` 与 `chart-plot`），
  各自都在自己的 bounds 内，几何完全合法 —— **跨组重叠不在 checker 的检查域**。
- **发现方式**：**渲染后人工视觉复核**（contact sheet + 单页放大）。这是本类缺陷
  **第二次**由人眼而非工具发现（第一次是 T-E2E3 的 C-011）。
- **修复**：引入独立的 `LEGEND_Y = 648`，图例整体下移一行；`note` 行下移至 `NOTE_Y = 692`，
  bounds 同步放宽到 `80 668 1120 44`。修复后 4 页的图例均落在类目标签下方独立一行。
- **推广建议**：见 §6-1（跨组重叠应纳入自动检查）。

### C-016 · progress 渲染器 6 项时溢出画布（**真实缺陷，已修**）

- **现象**：P13（六项进度条）最后两行超出 `chart-plot` 的 bounds，checker 报
  `blocking: 3`（垂直溢出 5.4%–10.1%）。
- **根因**：`render_progress` 初版写死 `row_h = 92`、`y0 = 210`，
  6 项时末行落到 `y=670`，超出 `bounds` 底边 650。
  按规则 `progress_bar_chart` 支持 **3-8 项**，故这是必然会被触发的几何缺陷。
- **修复**：行高自适应 `row_h = min(86, (612 - y0) / max(n-1, 1))`，
  使 3 项与 8 项都落在 `[200, 640]` 内；bounds 同步为 `60 130 1160 530`。
- **教训**：**渲染器必须按规则声明的项数上限自证**——规则说支持 8 项，
  就必须用 8 项跑一次；T-E2E3 只测了 4 项（bullet）与 4 柱（column），未覆盖上限。

### C-017 · 契约措辞与实现命名的错位（**记录，待改进**）

- **现象**：`fill_chart.py` 的 `column` 渲染器支持多序列并排，
  而 `charts_index.json` 规定"多序列应用 `grouped_bar_chart`，`column_chart` 应 Skip"。
- **影响**：P10 的选型在**实现层面没错**（几何正确），但在**契约措辞层面有偏差**。
- **处置**：如实记录于 §2「规则冲突处置」，并列入《建议》§6-3，不掩盖。

### C-018 · 脚本硬编码 `/mnt/d` 路径导致跨侧失败（**已修**）

- **现象**：`fix_hygiene.py` 首跑报 `FileNotFoundError: '/mnt/d/OpenCode_Spaces/PPT skill????/…'`。
- **根因**：脚本内写死 WSL 路径，却用 Windows Python 执行（本项目 WSL 对 `/mnt/d` 只读，
  写操作必须走 Windows 进程 → 路径语义不同）。
- **修复**：改为 `sys.argv[1]` 传入根目录。**规律**：本项目所有脚本的路径必须可注入，
  不能写死任一侧的路径。

### 《建议》

1. **补"跨组重叠"自动检查（优先级最高）**。C-011（内容泄漏）与 C-015（图例压字）是同一类
   问题的两面：**单组几何合法、但整体语义/视觉错误**。建议在 `deltas/pptx-fill-check/` 增
   一个 `check_overlap.py`：解析各根级 `<g>` 的 `data-pptx-bounds`，报告**非预期重叠**
   （放行母子组、放行刻意叠放的白名单）。这能把"必须人眼看"的范围再缩小一截。
2. **渲染器按规则上限自证**（C-016 的直接推论）。给 `fill_chart.py` 加一个 `--self-test`：
   对每个类型按其**声明支持的最大/最小项数**各生成一页并跑 checker。
   这样"支持 3-8 项"就不是文档里的一句话，而是会被自动验证的约束。
3. **`column` 渲染器改名或拆分**（C-017）。建议拆为 `column`（单序列）与 `grouped_bar`（多序列），
   与 base 的两个模板一一对应，消除契约措辞与实现的错位。
4. **补"内容泄漏"词表**（延续 T-FIX4 R3 的机制）。T-FIX4 建了词表但只覆盖骨架示例；
   建议把**上一 deck 的标题/品牌词**也纳入检查，防止跨 deck 的语境残留。
5. **`deltas/chart-fill/` 继续扩类型**。当前 6 类。T-05（BP 路演）需 `funnel`/`waterfall`
