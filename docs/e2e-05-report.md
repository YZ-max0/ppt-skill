## 4. 失败模式（C-XXX）

> **本轮最重要的发现**：三个缺陷都**通过了全部四道自动质检**
> （checker / hygiene / overlap / D-2 全绿），**全部由渲染后人工看图发现**。
> 这暴露了自动化闸门的能力边界：**它们只能证明"没违反已知规则"，不能证明"画对了"。**

### C-019 · 逆向指标被渲染成「超额完成」（**语义错误，四闸全漏，已修**）

- **现象**：P11"获客成本回收周期"目标 9 个月、实际 11 个月（**未达标**），
  却渲染成**蓝色 122%**，与页面标题"三项达标，**一项需加速**"直接矛盾。
- **根因**：`render_bullet` 统一按"实际 ≥ 目标 = 达标"判断，未区分**指标方向**。
  回收周期是**逆向指标**（越低越好），实际值偏大恰是**变差**。
- **为何四道闸都没拦住**：几何完全合法（条长、标尺、标签都在 bounds 内），
  hygiene/overlap 更与语义无关。**属"画对了形状、画错了含义"**。
- **发现方式**：**渲染后人工视觉复核**。
- **修复**：数据项支持 `lower_is_better: True`；判定改为 `actual <= target`（逆向）；
  达成率统一换算为 **>100% 恒为超额、<100% 恒为未达标**；
  行内加注"（越低越好）"消除歧义。修复后该行显示**橙色 82%**，与标题一致。
- **推广**：`fill_chart.py` 所有"目标 vs 实际"类渲染器（`bullet`/`progress`/`gauge` 族）
  都应支持方向标记。**建议列入渲染器自证清单**（见 §6-2）。

### C-020 · waterfall 柱体塌成一条线（**几何错误，已修**）

- **现象**：P08 六根柱子全部渲染成**约 3px 的细条**，桥式图完全读不出增减。
- **根因**：`py()` 把"值大"映射为"y 小"（屏幕坐标向下增大）。
  代码写成 `y0, y1 = py(min(a,b)), py(max(a,b))` 后再算 `h = max(y1 - y0, 3)`——
  此时 `y1 < y0` 恒成立，**高度恒为负**，被 `max(..., 3)` 全部压成 3px 底线。
- **为何四道闸都没拦住**：3px 矩形仍在 bounds 内、与文字不重叠，几何合法。
- **修复**：改名并澄清方向——`top_y = py(较大值)`、`bot_y = py(较小值)`、`h = bot_y - top_y`。
  修复后柱高分别为 333/44/33/22/33/266px，桥式关系正确可读。
- **教训**：**SVG 的 y 轴向下增大**。凡由数值求"高度/区间"都必须先想清方向。

### C-021 · funnel 窄段数值压住斜边（**视觉错误，已修**）

- **现象**：P09 漏斗下三段（2400/960/384）的白色数值标签**溢出段外**，
  `384` 几乎完全压在斜边与空白交界处，可读性差。
- **根因**：数值标签一律**居中**绘制，未考虑段宽随数值缩小——
  末段宽度仅为首段的 3.2%，放不下"384"的文本宽度。
- **修复**：先算 `vw_of(值) × font-size`；**超过段宽即把标签移到漏斗左侧外部**
  （右对齐到轴区左缘），并同步放宽 group bounds 到 `40 150 1180 470`。
- **教训**：**"放不下"要算，不能假设**——本仓库已有 `vw_of` 口径（capacity.py），应复用。
- **顺带**：这也是 `fill_chart.py` 第一次引入 `vw_of`，补齐了该工具此前缺失的文本宽度估算能力。

### C-022 · 卫生词表过宽导致真实内容误报（**误报，已修**）

- **现象**：T-FIX4 建立的 `check_hygiene.py` 词表把 T-05 的
  "接入企业自有**知识库**与工单历史"判为 P0 泄漏。
- **根因**：词表收录了 **`知识库`** 这一**通用业务名词**（来自 T-03 场景）。
  词表的判据应是"只可能来自骨架示例"，而通用名词在任何真实 deck 里都可能正常出现。
- **修复**：词表只留**完整短语**（`知识库平台建设方案`）+ 品牌缩写（`KB`）；
  新增 `GENERIC_DENYLIST`（知识库/平台/系统/数据/方案/客户…）并在命中时打印告警。
- **双向验证**：修复后 T-05 产物 exit 0（0 误报），
  历史泄漏样本仍被准确拦下（`知识库平台建设方案` / `KB` / `99.4%` 全部命中，exit 2）。
- **教训**：**词表的威力来自精确，不是宽度**。

## 6. 《建议》

1. **给四道闸加"语义层"是不够的——应加"渲染自证清单"**。C-019/020/021 说明：
   几何闸管不了语义。建议在 `fill_chart.py` 加 `--self-test`：
   每个渲染器按其**声明支持的最大/最小项数** + **逆向指标** + **窄段极值**各生成一页并跑
   四道闸 + 人工核图清单。把"渲染器必须自证"从口头纪律变成可执行步骤。
2. **`bullet`/`progress` 族统一支持 `lower_is_better`**（C-019 直接推论）。
   目前仅 `bullet` 支持；`progress` 与未来 `gauge` 同样会遇到逆向指标（完成率、故障率、账期）。
3. **把 `vw_of` 作为渲染器通用工具**（C-021 教训）。本次已在 `fill_chart.py` 内置；
   建议所有"文字进几何"的渲染器（funnel/waterfall 标签、柱顶数值）统一先算宽度再决定位置。
4. **词表变更需双向回归**（C-022 教训）。`check_hygiene.py` 的词表是**双刃**：
   加宽→误报真实内容，收窄→漏掉泄漏。建议词表变更后**必跑两个样本**：
   当前产物（应 0 误报）+ 历史泄漏样本（应被拦）。
5. **图表候选继续扩**。当前 9 类。T-06（评审答辩）可能需要 `comparison-rows` 类与
   `evidence-wall` 的组合；如遇 `charts_index` 无匹配的财务关系
   （如 unit economics 的**多层级摊分**），按卡内要求如实报告并给替代方案
   ——本轮 P08 用 `waterfall` 承载单位经济学，即属"规则内最贴近"的选择。
6. **导演式 B2 门禁的价值已被验证**。BP 单页密度与"一页一核心"的张力，
   正是靠 B2 的**面积预算**字段裁决掉的（见 §3 异议区）。
   建议把"面积预算"列为 B2 强制字段并在报告留痕。
