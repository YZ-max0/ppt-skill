## 4. 骨架复用中发现的摩擦点（C-XXX）

### C-004 · `check_title_consistency` 在同档不同角色文本上误报（🟡 已记录，未修复）

- **现象**：T-01b 产物报 1 项 P1：
  `text@18-21: 标题 '进度符合预期，两项风险已有对策' 字号 18.0pt 偏离该级常规 21.0pt（差 3.0pt）`
- **根因**：该档 7 个成员 = 封面副标题(18pt) + 4 个编号(21pt) + 2 个卡片标签(21pt)。
  主导占比 6/7 = **0.857 ≥ 0.6**，通过门槛，于是报了那个 18pt。
  但这三者是**不同角色的文本**，不构成"同级字号漂移"。
- **定性**：分档法的固有边界的**另一面**——README 已声明"跨档漂移不可检"；
  本条是"**同档不同角色会误判**"。二者都源于"无角色信息"这一前提。
- **影响**：free-design 产物上 P1 可能有噪声（本次 1/16）。
- **建议**：见 §5 建议 1。

### C-005 · `project_manager.py init` 忽视 PowerShell 的 `cd`（🟢 已绕行）

- **现象**：`powershell -Command "cd <dir>; python project_manager.py init foo"` 时，
  项目未建在 `<dir>`，而是建在**默认 projects 根**（`C:\...\Temp\opencode\projects\`）。
- **原因**：`cd` 在 PowerShell + python 子进程组合下的工作目录传递未按预期生效
  （与 `docs/windows-notes.md` W-3 同源：跨侧路径/目录上下文问题）。
- **绕行**：改用 `Set-Location -LiteralPath '<win path>'`，或接受默认根并在该根下作业。
- **建议**：补进 `docs/windows-notes.md`（见 §5 建议 3）。

### C-006 · 骨架几何需按"最坏文案"验证（🟢 已内化为设计原则）

- **现象**：首轮 2/6 骨架因占位文案过长触发 checker 越界（P04 节点三、P05 指标三）。
- **处理**：把占位文案写成"最长合理内容"，把 checker 当容量标尺用，一次验证到位。
- **价值**：这一原则让"填充时无需试探 bounds"成为可能（本卡硬约束 2）。
- **建议**：写入 CONTRACT（已写 §3/§4）。

## 5. 《建议》附录

### 建议 1 【优先级中】C-004 的缓解：为 free-design 引入"角色提示"

当前分档法只有字号一个维度，必然混淆"同档不同角色"。可选缓解（按性价比排序）：
1. **文本特征辅助分档**（低成本）：编号类（`01`/`02`，纯数字 2 字符）、短标签（≤4 字）与
   长句副标题在**同一档内再分组**，组间不比较。本次 C-004 的两个 21pt 成员恰是"2 字符编号"
   与"2–3 字符标签"，而 18pt 是长句，特征区分度高。
2. **提高 `--dominance-min`**（零成本调参）：本次 0.857 仍报，需提高到 >0.857 才能压掉，
   但这会同时压掉真阳性。**不推荐**。
3. **骨架标注角色**（中长期）：在资产库骨架里用 `data-pptx-role` 或注释标记"这是页标题 /
   卡片标签"，让检测器有角色依据。与建议 2 的 workspace 化方向一致。

> 我的评估：方案 1 性价比最高，建议单独开卡；方案 3 与版式资产库 v1 一起做。

### 建议 2 骨架库 → base `create-layout` workspace 升级路径评估

**现状（v0）**：合规 SVG 骨架 + CONTRACT 文本契约。优点：立即可用、零 vendor 依赖、已验证。
**升级（v1+ 候选）**：转为 base 原生 `create-layout` workspace，收益与成本：

| 维度 | v0（现形态） | workspace 化 |
|---|---|---|
| 可用性 | ✅ 立即 | 需先跑 Create Template 流程 |
| 与 base 集成 | 靠人工"复制文件+替换文本" | ✅ 可被 Generate Stage-1 直接选为模板候选 |
| 角色信息 | ❌ 无（C-004 根源） | ✅ Layout/Placeholder 天然带角色 |
| 可维护性 | 6 个独立 SVG，改版需逐个改 | ✅ 单一 workspace，集中管理 |
| 成本 | 已投入 | 需重做为 Create Template 产物 + 验证 |

**建议**：**v0 先服务 M1 测试集**（T-02~T-06），在真实使用中收集"哪些页型真正被复用"；
**待页型稳定后**（预计 10-12 个骨架）再一次性 workspace 化，避免过早重做。
**不建议现在升级**——v0 的价值还没被测试集验证完。
