### 2.4 两个示例对话（验收样本）

**例 1 · "帮我做一份下周团队周报"**（快通道走查）

```
用户：帮我做一份下周团队周报
 你 ：好。一份就够，还是需要我先给你看个结构？（其他：你直接定）
用户：你直接定
 你 ：明白，我按"简洁出稿"来做，6 页走：封面 / 本周完成 / 风险与对策 /
      下周计划 / 关键数据 / 小结。
      假设（会写进交付说明）：受众=你的直属主管；内容为通用团队模板；
      数据为占位，需你回填。约 5 分钟出稿。
用户：可以
```

> 走查要点：**1 轮追问、1 个问题、带"你来定"**；随后直接开工，
> 并在同一段里**列清假设**（受众/内容/数据三项）。

**例 2 · "下周要给分管领导汇报平台建设方案"**（质量协议走查）

```
用户：下周要给分管领导汇报平台建设方案
 你 ：这份是要快，还是要尽可能做好？（没特别说的话，我按"尽可能做好"来做）
用户：尽量做好
 你 ：好。两件事确认一下就可以开工：
      ① 分管领导最关心的是投入产出，还是落地节奏和风险？
      ② 这次是上台讲，还是交材料给他看？（其他：你来定）
用户：关心投多少钱、多久见效。要讲的，大概 20 分钟
 你 ：收到。20 分钟 + 决策者 → 我走完整打磨流程，页数按 18–22 页。
      视觉给你三个方向，看哪个顺眼：
      - A 稳重款：白底为主，蓝色主色，数据用大字和表格
      - B 醒目款：封面和关键页用深色大色块，数据用图表
      - C 均衡款：A 打底，关键 3–4 页用 B 的手法做重点
      （其他：你直接定，我倾向 C）
用户：B 吧
 你 ：好，视觉用 B。最后一项：要不要逐字稿？（每页可照念的口语稿，按 20 分钟配速）
用户：要
 你 ：齐了，开工。开始前说一句我打算怎么做：先把"给谁讲、他关心什么、
      讲完希望他拍什么板"定死，再逐页列出每页要说的结论，然后做视觉、
      挑刺、出稿。做完先给你一页缩略总览过目。
      假设：经费与工期数字需你提供；未提供前我用占位并标注。
```

> 走查要点：**「你」共 5 个发言块**（入口 1 + 追问 2 + 视觉 1 + 收尾 1），
> **合计 4 个问号，单轮最多 2 问**（满足 N-3）；
> **3 个发言块带"你来定/你直接定"**（满足 N-2）；
> 覆盖了入口二分 → 受众关注点 → 讲/看 → **视觉候选展示** → **逐字稿询问** →
> 开工前复述方法与假设。**全程零内部术语。**

### 6.1 计数分歧的排查（W-2 的又一实例）

`wc -l` 报 **200** 行，而 PowerShell `Get-Content | Measure-Object -Line` 报 **143**。
**判定：200 为准。** 排查过程：

| 测法 | 结果 |
|---|---|
| WSL `wc -l` | 200 |
| WSL python `t.count("\n")` | 200 |
| Windows `[IO.File]::ReadAllText` 字符数 | 3648 |
| Windows 该文本中 LF 数 | **200** |
| Windows 该文本中 CRLF 数 | 0 |
| PowerShell `Get-Content` 行数 | **143** ← 异常值 |

**根因**：PowerShell 5.1 对**无 BOM 的 UTF-8** 文件默认按系统 ANSI（GBK）解码；
GBK 前导字节（0x81–0xFE）会把后随的 `0x0A` 当作**双字节字符的第二字节吞掉**，
于是部分行尾 LF 消失，行数凭空少计。文件本身是完好的 200 行。

> 这正是 `docs/windows-notes.md` **W-2**「控制台编码会误导判定，看文件字节」的又一实例。
> **建议**：行数/字符数这类校验一律用**字节级统计**（python 或 `[IO.File]`），
> 不要用 `Get-Content`（受默认编码影响）。

## 8. 《建议》

1. **把术语审计做成常驻检查**。本次审计脚本是一次性的。建议在
   `deltas/layout-assets/check_hygiene.py` 旁边加一个轻量 `check_terms.py`：
   扫描面向用户的文档（`README.md` / `docs/USAGE.md` / `docs/QUALITY-TIERS.md` /
   `deltas/intake-guide.md`），命中禁用词表即告警。这样术语禁令才是"有牙齿的"。
2. **给视觉候选一个低成本呈现方式**。guide 承诺"展示 2–3 个候选"，但当下的产出成本是
   "各渲染一页"。建议做一个"候选说明卡"模板：一句话风格描述 + 一页代表页缩略图即可，
   不必整 deck 渲染三遍。
3. **把示例对话扩到覆盖边界情况**。当前 2 个示例都是"顺利路径"。建议补：
   ① 用户全程跳过所有问题；② 用户在第 3 轮才说"其实受众不是领导"；③ 用户只要一个单页。
   这三种情况最考验 N-2/N-3 与"中途改主意"的处理。
4. **`≤12 页` 阈值待实测校准**。当前沿用卡内值。建议在后续真实使用中记录：
   轻量稿产出是否需要返修、返修原因是否属"内容没想清楚"——若是，则降低阈值。
5. **README/QUALITY-TIERS 的计数应有单一来源**。本次又发现"24 vs 29"的失实
   （与 T-FIX4 的"知识库"词表问题同类：**文档随实现漂移**）。
   建议骨架数由脚本统计后写入，或文档中改为"约 30 个（详见 `deltas/layout-assets/`）"
   以避免频繁失实。
