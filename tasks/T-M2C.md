# 任务卡 T-M2C · 使用入口与手册（产品化收尾）（P1 · 预计 2-3 小时）

指挥官：opencode ｜ 执行者：同一执行者 ｜ 版本：v1.0 ｜ 前置：T-M2B-R1 已关闭

## 背景

项目能力完备（24 骨架 / 两条工作流 / 质检器 / 渲染管线 / 视觉增强），但**没有任何面向使用的入口文档**。
本卡完成后用户将亲自实测——手册必须先能让人"拿起就用"。

## 交付物 1 · `README.md`（repo 根，≤120 行）

- 项目一句话定位（基于 ppt-master 基座 + 导演工作流 + 骨架资产库的 PPT 制作系统）
- 两条路线 30 秒介绍（快速通道 / 导演式）
- **快速上手 5 步**（从"我有一个主题"到"拿到 .pptx"）
- 目录导航（vendor / deltas / tests / docs 各自是什么）
- 限制摘要（W-1~W-8 一句话 + 指向 windows-notes）
- 许可声明（MIT 基座 + 本地增量）

## 交付物 2 · `docs/USAGE.md`（使用手册，≤300 行）

1. **路线选择指南**：什么时候走快速通道（≤8 页/时效紧），什么时候走导演式（重要汇报/≥10 页）
2. **逐步操作**（真实命令示例，每一步给"你会看到什么"）：
   发起请求 →（导演式：受众卡→导演稿→B2）→ 选骨架 → 填充 → `svg_quality_checker` → `svg_to_pptx` → D-2 质检 → 渲染验证
3. **骨架库索引**：24 骨架一览表（名称 / 用途 / 来源版本 / 适配页型）
4. **常见场景配方**：例如"周报 6 页"推荐骨架组合；"方案 20 页"推荐组合（基于 T-01/T-03 实战）
5. **工具用法**：checker / D-2 / render_png 的调用示例与结果解读
6. **环境注意**：W-1~W-8 摘要表（指向 windows-notes 详情）
7. **能力边界**：模板填充 vs free-design 的质检差异、同页检测移除、单渲染器依赖等
8. **如何发起一次制作**（给 AI 执行者的请求模板）：包括主题/受众/页数/时长/素材/风格偏好六个输入项

## 交付物 3 · 手册自测（doc-test，必做）

发现的任何文档-现实偏差当场修正（修正记录入报告）。

## 交付物 4 · `docs/m2c-usage-report.md`

doc-test 结果 + 修正清单 + 《建议》。

## 硬约束

1. 只新增 README.md / USAGE.md / 报告；不修改 vendor 与既有 deltas 代码（文档中引用它们为准）
2. 手册中所有路径、命令、文件名与 repo 现状一致（写前列 actual 清单核对）
3. 不复制 vendor 大段文档（引用其路径为准）；不暴露内部治理细节（decisions/台账是维护文档，手册只留入口链接）
